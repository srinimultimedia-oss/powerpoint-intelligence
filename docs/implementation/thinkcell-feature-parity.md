# think-cell observable feature parity audit

Audit date: 26 October 2026 (Asia/Dubai). Baseline: the v15 source and its recorded execution evidence, before the current ribbon expansion. This is an engineering gap register, not a statement of feature equivalence or a specification of proprietary internals.

## Boundary and evidence quality

This audit reads public vendor manuals, the add-in source and existing test artifacts. It does not inspect/decompile vendor binaries, extract protected implementation details, copy vendor artwork, or invoke vendor automation to simulate an independently implemented feature. The external original-template integration approved in AD-016 remains a file dependency, not a recreation of the vendor editing engine.

Public documentation describes the current vendor offering; the installed reference observed earlier is version 15.0.102.172. Edition/version availability can differ. A published behavior is documentation evidence, not proof that it was exercised on this computer. No complete vendor command inventory or complete runtime workflow capture has been obtained, so this is a bounded parity audit rather than an exhaustive certification.

Current product evidence:

- `DemoTools.cs` contains 90 local commands. A command name, tooltip, icon or callback is not evidence of full matching semantics.
- `FeatureInventory.cs` and the production traceability JSON already call most areas partial/not accepted. Their older notes can lag newer code and do not override execution logs.
- Desktop `artifacts/validation-20261026-155936-44d22bed`: 25 PASS / 3 FAIL, including installed ribbon identity/OnLoad/hash, native renderer persistence and three S0 adapter runs passing. Full process restart/task-pane visuals are separate gates.
- Desktop `validation-20261026-161730-bc82f220`: six original source slides pass exact insertion pixels/object counts/build/transition/cleanup, then a Pyramid differs by eight grayscale edge pixels. Original-source edit/save-reopen was not accepted by that run. Demo report output is 1 PASS / 2 FAIL / 87 BLOCKED, not 90 accepted commands.
- Latest recorded v15 local suite `validation-20261026-165627-20879fae`: 20 PASS / 1 FAIL, including all architecture compile targets and 41 renderer core tests. The x64 scene executable has a recorded quarantine-hash/receipt mismatch and remains held. Local geometry/contracts do not establish native feature parity.
- Source-library gallery screenshot uses seven captured native renders through an injected provider. Its local UI tests do not prove deployed PowerPoint interaction or all 497 source previews.

## Current v17 implementation increment

The baseline matrix below remains a record of the earlier audit. The current source adds a bounded native subset, not full parity:

- Ten workflow ribbon groups; all 90 existing commands retained once, plus 26 new workflow commands. Selection-aware enablement and original icons are contract-tested.
- Section-based managed agendas with explicit refresh, stable native slide targets and editable fields. Nested chapters and synchronized agenda propagation are not implemented.
- Chart-linked reference/difference annotations with persisted identities and explicit refresh for supported unstacked primary linear axes. Automatic layout/recalculation, totals, CAGR binding and unsupported chart families remain gaps.
- Linked text-capable tables rather than hardcoded sample cells, bounded to 400 cells.
- Native primary value-axis bounds, interval, format, reversal, linear/logarithmic mode and cross-chart scale matching. No drag handles, axis breaks or complete date-axis editor.
- Selected-series conversion among unstacked column/line/area types and optional secondary axis, with preflight and rollback. This is not the complete chart editor.
- Selected native text/shape/group/table formatting: fill/outline/text RGB pickers, paragraph/vertical alignment and text orientation. Gradient/pattern fills and unsupported targets are preserved/refused; formatting has bounded reversible changes.
- Read-only quality review with Locate: bounded off-slide, empty text, small font, hidden-slide and picture-alt-text heuristics. It is not a sanitization engine or accessibility certification.
- Native whole-presentation PDF export; no email, ZIP or sanitized-copy sharing pipeline.
- Explicit Excel sheet/range/columns in version-2 source records; legacy v1 references still decode. A compatible native chart can be refreshed manually through the Data Link Manager. Header/dimension changes stop refresh; explicit selected-object relinking requires confirmation and retains previous source registry entries. Automatic/multi-object refresh, full range editing and table/diagram refresh remain incomplete.
- Nonsecret service configuration for Azure OpenAI, on-prem data and assets. No authenticated service request or AI result is implemented or claimed.

New deterministic checks and desktop regression scenarios are in `docs/implementation/parity-v17-validation.md`. Full think-cell parity remains **incomplete and unaccepted**. Earlier desktop results do not transfer to this source build.

## State definitions

- **Native subset**: corresponding PowerPoint objects/commands are implemented; scope is narrower than vendor behavior and runtime acceptance is still feature-specific.
- **Approximation**: an intentionally reduced demo behavior exists and cannot be labelled as the vendor feature.
- **Missing**: no matching implementation found in this bounded source review.
- **External / not configured**: live services are in scope under AD-017 but endpoints/identity/policy are not configured and no authenticated operation has been accepted.
- **Source dependency**: an external original file is used; this is neither independent recreation nor redistribution.

## Priorities for implementation and ribbon exposure

1. **Correct semantic misrepresentations first.** Fix hardcoded table insertion, avoid calling row transposition a rotated profile, and keep sample-only annotations explicitly labelled until genuinely data-bound. Do not add functional-looking controls that silently do nothing.
2. **Promote existing real tools into discoverable task groups.** Structure/Elements/Data/Text/Layout/Color/Quality/Collaboration/More can organize working controls. Native selection/compatibility checks should disable incompatible commands with actionable explanations. Preserve unique IDs, original icons, keyboard access and installed-source validation.
3. **Add independently testable behavior before broad interactive chart work.** A selected-chart data editor, typed geometry/scale planner, linked annotation model/calculations, or explicit managed agenda IDs can each have pure contracts and a bounded native adapter. Each needs edit/save/reopen/duplicate/rollback evidence.
4. **Build a real data-link lifecycle.** Stable source/range mapping and approved moved-file behavior are needed before auto-refresh/batch/revert claims. Honor Q-010 instead of silently choosing a rebinding policy. Store the last accepted data and validate before mutation.
5. **Advance complex chart engines as real domains.** Waterfall totals/connectors, Gantt dates/milestones/dependencies, Mekko semantics and label/axis layout require models and deterministic geometry, not more ribbon aliases for the same static diagrams.
6. **Close execution gates.** The quarantine/receipt mismatch, original-template edge-pixel discrepancy, workbook-close failures and blocked demo scenarios remain open. A new group layout must not erase their status or inherit test results from an older build.

## Acceptance rule for this register

A row can advance only with explicit implemented behavior plus corresponding executed evidence. For native features record Office executable/build/architecture, inserted object kind, edits, persistence, copy/duplication behavior and failure/rollback results. For public-documentation observations preserve the URL and version/scope limitations. Full think-cell parity is **not implemented, exhaustively inventoried or verified** by this audit.
