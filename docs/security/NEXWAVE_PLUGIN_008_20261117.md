## Source changes

- easySetup/Bootstrapper.cs: VerifyPackage normalizes ZIP entry backslashes to forward slashes, validates safe relative paths, rejects duplicate/case/separator aliases, verifies inventory/count/file hashes before extraction, and returns the verified entry objects. GUI extraction uses those exact objects through ExtractPackage; neither phase performs a second incompatible GetEntry lookup. Existing-file modification refusal, bundle digest, size bounds and normal VSTO publisher flow remain enforced.
- SafePath additionally rejects empty/dot/parent/trailing-dot/trailing-space segments to prevent normalization aliases. Inventory keys remain forward-slash only; accepting legacy ZIP separators does not permit traversal or alternate streams.
- easySetup/Common.ps1: New-EasySetupPayloadZip is the shared actual producer. It explicitly loads System.IO.Compression and System.IO.Compression.FileSystem for Windows PowerShell5.1, then creates every entry with a forward-slash relative name. A desktop retry exposed the missing enum assembly in the first revision; that failed attempt is retained as superseded evidence, not a success.
- easySetup/Build-EasySetup.ps1: uses the shared writer and invokes Test-EasySetup -SourceOnly -BundlePath against the exact staged ZIP before embedding/signing/publication. A hash-valid but structurally unusable payload now fails before publishing.
- easySetup/SetupPolicyTests.cs and Test-EasySetup.ps1: production verifier/extractor/writer regression coverage, actual-bundle verification and normal signed receipt checks.

No trust store, execution policy, antivirus setting, COM registration or application chart/template functionality was changed.
